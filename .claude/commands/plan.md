description: Turn the deadlines and the current state into a dated work plan

Read `DEADLINES.md`, `TARGETS.md`, every file in `applications/` and `drafts/`, and
`GAPS.md` if it exists. Run `tools/count.sh` for the real draft state. Write `PLAN.md`.

`/status` says what is true right now. This says what to do on which day, working
backward from the deadlines that exist.

## Work backward, not forward

Start from the earliest deadline and subtract. The things that must happen before the
day of submission, in the order they bind:

1. **Anything depending on another person.** Recommenders, letters of support, a
   teammate's piece, a video someone has to film with you. These have the longest lead
   time and no amount of effort on your side compresses them. If a recommender needs
   three weeks and the deadline is in two, say that in the first line of the plan.
2. **Anything institutional.** Official transcripts, campus nomination steps,
   eligibility registration, portal accounts. These take days and cannot be done at
   11pm.
3. **Material that has to come out of the applicant.** Open `[NEED:]` markers, the
   Section A questions in `GAPS.md`. Nothing gets drafted past these.
4. **Drafting**, cluster by cluster, writing the source application in each cluster
   first so the rest adapt from it.
5. **The review passes**: `/truth`, `/slop`, `/reader`, then `/submit`.

## The plan itself

Dated, one block per day, from today to the last deadline. For each day: the specific
thing, roughly how long it takes, and what it unblocks. Not "work on essays."

Rules that keep it honest:

- **Never schedule drafting on the deadline day.** That day is for `/submit` and for
  whatever breaks.
- **Put the cluster source application early**, since everything after it is faster.
- **Cap it at what a person actually does in a day** alongside classes or a job. Three
  hours of real application work is a full evening. A plan that assumes eight is a plan
  they will abandon on day two, and then they will not trust the file.
- **Name the day the recommender ask goes out**, and make it the earliest day in the
  plan that it can be.
- If two deadlines land the same day, say which one gets the good hours and why.

## The honest part

End with two things.

**What is at risk.** Any deadline the plan does not comfortably clear, named, with what
would have to give. If the list of targets cannot all be done well, say so and say
which one you would drop. That is a real answer, and hearing it two weeks out is worth
more than hearing it the night before.

**The single thing that unblocks the most.** Usually one `GAPS.md` section or one
recommender email. Put it on today.

Rewrite this file rather than appending when it is run again. A stale plan is worse
than none.
